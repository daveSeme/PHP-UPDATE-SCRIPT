PHP 8.2.27 → PHP 8.2.35

A practical upgrade, validation, and rollback guide for a Yii application running on IIS with PHP Non-Thread-Safe (NTS) x64.

Windows ServerIIS FastCGIPHP NTS x64Yii application
Before you start Run PowerShell as Administrator, schedule a maintenance window, and ensure you have a tested application/database backup. This guide uses example paths and names: replace them with the actual paths, IIS site, handler, and app-pool names on your server. Do not paste commands blindly into production.
Version and download check Confirm that PHP 8.2.35 is the exact approved build for your environment and that the archive is available from the official PHP for Windows distribution. PHP 8.2.35 is not necessarily the newest 8.2 security patch. Prefer the latest supported security patch approved by your organization. Download only from an official, trusted source and verify the package before deployment.

Overview

The safer approach is to install PHP 8.2.35 into a new folder, keep PHP 8.2.27 untouched, test the new binary, then change only the relevant IIS FastCGI handler. This makes rollback much easier than overwriting the existing PHP directory.

SettingExample valueAction
Old PHP folderC:\PHP\8.2.27Keep intact for rollback
New PHP folderC:\PHP\8.2.35Install new version here
PHP modeNTS x64Must match IIS FastCGI deployment
PHP executable for IISC:\PHP\8.2.35\php-cgi.exeSet handler to this executable
Configurationphp.iniCopy and review; do not assume every extension is compatible

If your current PHP is installed directly in C:\PHP, use that actual path for the old installation and adjust the new path to fit your server conventions.

1. Inspect the current server

Open PowerShell as Administrator. Record the current PHP version, configuration file, extension directory, IIS sites, handlers, and application pools before making changes.

PowerShell · inspect current PHP
# PHP command resolution and version
php -v
where.exe php
php --ini
php -i | Select-String "Architecture|Thread Safety|Compiler|Loaded Configuration File|extension_dir"

# IIS appcmd
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"
& $appcmd version
& $appcmd list sites
& $appcmd list apppools
& $appcmd list config /section:system.webServer/fastCgi
& $appcmd list config /section:system.webServer/handlers
Save the output somewhere safe. The php command in PowerShell may resolve to a different PHP binary than IIS uses. IIS's FastCGI scriptProcessor path is the key setting for the web application.

Record these values

  • Exact old php-cgi.exe path.
  • Exact IIS site name and PHP handler mapping name.
  • Application pool name for the Yii site.
  • Old php.ini and the list of enabled extensions.
  • Database connectivity details and current Yii logs/errors.

2. Back up before changing IIS

1

Create an IIS configuration backup

PowerShell · Administrator
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"
& $appcmd add backup "BeforePHP8235"
2

Back up the existing PHP folder

Change the source path to your actual current PHP folder. Example:

PowerShell
robocopy "C:\PHP\8.2.27" "C:\PHP_backup_8.2.27" /E /COPY:DAT /DCOPY:DAT /R:1 /W:1
if ($LASTEXITCODE -ge 8) { throw "PHP backup failed. Stop here and investigate." }

Robocopy exit codes 0–7 are generally non-fatal; 8 or above indicates a copy failure. Check the output and verify the backup exists.

3

Back up the Yii application and database

Use your organization's normal backup process. This PHP change should not require a schema migration, but a recoverable backup is still essential.

3. Download and extract PHP NTS x64

Verify the exact release filename and URL on the official PHP for Windows site before running the download. The URL below is an example target; if it returns 404 or the release is not listed, do not use a third-party mirror or substitute an unverified archive.

PowerShell · download and extract
$ErrorActionPreference = "Stop"

$work = "C:\PHPUpgrade"
$newPhp = "C:\PHP\8.2.35"
$zip = Join-Path $work "php-8.2.35-nts-Win32-vs16-x64.zip"
$url = "https://downloads.php.net/~windows/releases/php-8.2.35-nts-Win32-vs16-x64.zip"

New-Item -ItemType Directory -Path $work -Force | Out-Null
New-Item -ItemType Directory -Path $newPhp -Force | Out-Null

# Confirm this exact official URL and release filename before running.
Invoke-WebRequest -Uri $url -OutFile $zip

# Inspect the downloaded file before extraction.
Get-Item $zip | Select-Object FullName, Length, LastWriteTime
Get-FileHash $zip -Algorithm SHA256

Expand-Archive -LiteralPath $zip -DestinationPath $newPhp -Force

# Confirm expected binaries exist.
Test-Path (Join-Path $newPhp "php.exe")
Test-Path (Join-Path $newPhp "php-cgi.exe")
Test-Path (Join-Path $newPhp "ext")
If any expected file check returns False, stop and inspect the extracted directory. Do not point IIS at a folder until you have confirmed it contains the expected PHP binaries. Compare the SHA-256 hash against an official published hash if one is available.

4. Configure and test the new PHP installation

Prepare php.ini

Use the old configuration as a reference. Preserve application-required settings, but review every extension and path. Never copy an old php.ini blindly without checking paths and compatibility.

PowerShell · create initial configuration
$newPhp = "C:\PHP\8.2.35"
Copy-Item "$newPhp\php.ini-development" "$newPhp\php.ini"

# Open the new configuration in Notepad.
notepad "$newPhp\php.ini"

In the new php.ini, set at minimum the correct extension directory and review the settings below. Values are examples; preserve your existing production values where appropriate.

php.ini · illustrative settings
extension_dir = "C:\PHP\8.2.35\ext"
date.timezone = "Africa/Nairobi"
log_errors = On
display_errors = Off
  • Compare the old and new INI files and migrate required settings, such as memory limit, upload limits, timezone, error log, session settings, and any Yii-required extensions.
  • Enable only extensions required by the application, for example curl, mbstring, openssl, pdo_mysql or the database driver your app actually uses, fileinfo, gd, intl, and zip.
  • Ensure extension DLLs are from the same PHP release/build, architecture, and NTS package. Check any external DLL dependencies.
  • Keep display_errors=Off in production; log errors instead.

Test the PHP CLI and modules

PowerShell
$newPhp = "C:\PHP\8.2.35"
& "$newPhp\php.exe" -v
& "$newPhp\php.exe" --ini
& "$newPhp\php.exe" -m
& "$newPhp\php.exe" -i | Select-String "Architecture|Thread Safety|Compiler|Loaded Configuration File|extension_dir"

Confirm that the loaded configuration file is the new php.ini, thread safety reports disabled, the architecture is x64, and all required extensions load without startup warnings.

5. Configure IIS FastCGI

First inspect the current FastCGI applications and handler mappings. You may need to add a new FastCGI application and update the PHP handler for the specific site. Do not change a shared/global mapping unless you intend every dependent site to move to the new PHP version.

Register the new FastCGI executable if needed

PowerShell · IIS appcmd
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"
$newCgi = "C:\PHP\8.2.35\php-cgi.exe"

# Inspect existing entries first.
& $appcmd list config /section:system.webServer/fastCgi

# Only if the exact new path is not already registered:
& $appcmd set config /section:system.webServer/fastCgi "/+[fullPath='$newCgi']" /commit:apphost

Update the PHP handler mapping for the target site

Replace Default Web Site and PHP_via_FastCGI with the exact names found in your IIS configuration. Confirm the handler is the intended PHP handler before changing it.

PowerShell · example only
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"
$siteName = "Default Web Site"
$handlerName = "PHP_via_FastCGI"
$newCgi = "C:\PHP\8.2.35\php-cgi.exe"

# Review the target site's handler list before modifying it.
& $appcmd list config "$siteName" /section:system.webServer/handlers

# Update only after verifying the site and handler names.
& $appcmd set config "$siteName" /section:system.webServer/handlers "/[name='$handlerName'].scriptProcessor:$newCgi" /commit:apphost

# Review the resulting handler mapping.
& $appcmd list config "$siteName" /section:system.webServer/handlers
IIS configuration syntax can differ based on whether a handler is inherited, defined at site level, or configured in a web.config. If appcmd reports that the mapping cannot be found, stop and inspect the existing configuration rather than repeatedly trying variations. Keep a copy of the original handler configuration.

Recycle the correct application pool

PowerShell
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"
$appPool = "REPLACE_WITH_YOUR_APP_POOL"

& $appcmd recycle apppool /apppool.name:"$appPool"

6. Verify the website and Yii application

  1. Use a temporary, access-restricted diagnostic PHP file in the actual site root.
  2. Visit it locally or through the approved internal test URL and confirm the web runtime reports PHP 8.2.35.
  3. Check the loaded INI file, extension list, and error log.
  4. Test login, database access, key Yii pages, uploads, sessions, scheduled jobs, and any APIs that depend on PHP extensions.
  5. Delete the diagnostic file immediately after verification. Do not leave phpinfo() exposed on a public website.
Temporary diagnostic file · version-check.php
<?php
header('Content-Type: text/plain; charset=utf-8');

echo 'PHP_VERSION=' . PHP_VERSION . PHP_EOL;
echo 'PHP_SAPI=' . PHP_SAPI . PHP_EOL;
echo 'PHP_INT_SIZE=' . PHP_INT_SIZE . PHP_EOL;
echo 'LOADED_INI=' . (php_ini_loaded_file() ?: '(none)') . PHP_EOL;
echo 'EXTENSION_DIR=' . ini_get('extension_dir') . PHP_EOL;

echo 'PDO=' . (extension_loaded('PDO') ? 'yes' : 'no') . PHP_EOL;
echo 'cURL=' . (extension_loaded('curl') ? 'yes' : 'no') . PHP_EOL;
echo 'mbstring=' . (extension_loaded('mbstring') ? 'yes' : 'no') . PHP_EOL;

The file reports runtime details only; it does not prove the full application is healthy. Remove it as soon as checks are complete.

PowerShell · remove diagnostic file
# Replace with the actual site-root path.
Remove-Item "C:\inetpub\wwwroot\version-check.php" -Force

Rollback options

Choose the least disruptive rollback that matches what changed. The preferred quick rollback is to point the same site's PHP handler back to the old php-cgi.exe, then recycle its app pool.

OptionUse whenWhat it restoresRisk / note
A. Handler-only rollbackThe new PHP runtime fails after switching IIS.Handler points back to PHP 8.2.27.Usually the fastest option; restore old INI separately if changed.
B. Restore old php.iniThe old runtime now reads a modified configuration.Previous PHP settings and extension configuration.Restore to the exact path IIS/old PHP uses.
C. IIS configuration backupSeveral IIS settings changed and a broader restore is necessary.IIS configuration from a named backup.Can revert unrelated IIS changes made after the backup. Use only after assessing impact.
D. Full server recoveryThe server or application remains unhealthy beyond PHP/IIS config.Server/app/database state according to your backup plan.Follow your organization's disaster-recovery process.
Keep both PHP folders during the observation period. Do not delete PHP 8.2.27, its configuration, or the IIS backup until the upgraded Yii application has passed acceptance checks and the rollback window has closed.

Option A — manually switch the handler back

Use the actual previous PHP CGI path and the same IIS site/handler names you recorded before the upgrade.

PowerShell · manual handler rollback
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"

$siteName = "Default Web Site"                  # Change this
$handlerName = "PHP_via_FastCGI"                # Change this
$oldCgi = "C:\PHP\8.2.27\php-cgi.exe"           # Change to the real old path
$appPool = "REPLACE_WITH_YOUR_APP_POOL"         # Change this

if (-not (Test-Path $oldCgi)) {
    throw "Old PHP CGI executable not found: $oldCgi"
}

# Review the target mapping first.
& $appcmd list config "$siteName" /section:system.webServer/handlers

# If the old CGI path is not registered in FastCGI, register it.
# Inspect the existing FastCGI list before running this command.
& $appcmd list config /section:system.webServer/fastCgi

# Run the next line only if the exact old executable is not registered:
# & $appcmd set config /section:system.webServer/fastCgi "/+[fullPath='$oldCgi']" /commit:apphost

# Point the verified site handler back to the old executable.
& $appcmd set config "$siteName" /section:system.webServer/handlers "/[name='$handlerName'].scriptProcessor:$oldCgi" /commit:apphost

# Recycle only the affected app pool.
& $appcmd recycle apppool /apppool.name:"$appPool"

# Inspect the resulting mapping.
& $appcmd list config "$siteName" /section:system.webServer/handlers

Then restore the original PHP 8.2.27 php.ini if it was modified, browse the Yii application, check logs, and confirm the web runtime reports 8.2.27.

Option B — restore the saved php.ini

Use the backup you created before upgrading. Confirm the source and destination paths before copying.

PowerShell · example only
# Example paths only: replace with your actual backup and old PHP paths.
$iniBackup = "C:\PHP_backup_8.2.27\php.ini"
$oldIni = "C:\PHP\8.2.27\php.ini"

if (-not (Test-Path $iniBackup)) { throw "INI backup not found: $iniBackup" }

Copy-Item -LiteralPath $iniBackup -Destination $oldIni -Force

If your old PHP configuration was stored elsewhere, use that exact original location. Avoid overwriting the old configuration with the new PHP 8.2.35 INI.

Option C — restore a full IIS backup (high impact)

Only use this when a broader IIS rollback is intended. First review the available backups. Restoring the whole IIS configuration can undo unrelated site, binding, certificate, or application changes made since the backup.

PowerShell · review backups
$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"
& $appcmd list backup

After reviewing impact and obtaining approval, the IIS restore command for a named backup is:

PowerShell · use only after approval
# HIGH IMPACT: restores IIS configuration from the named backup.
# It may revert unrelated IIS changes made since that backup.
& $appcmd restore backup "BeforePHP8235"

PowerShell rollback script

This script is intentionally interactive. Save it as Rollback-PHP-8235.ps1, review/edit the default paths and names, then run it in an elevated PowerShell window. It changes the selected site's handler and recycles the selected pool; it does not delete PHP folders or restore the entire IIS backup.

Do not run with example values unchanged. Replace the site, handler, app-pool, and old CGI path with values recorded from your own server. Confirm that the selected handler belongs to the intended site.
PowerShell · Rollback-PHP-8235.ps1
# Rollback-PHP-8235.ps1
# Run PowerShell as Administrator.
# This script switches one IIS site's PHP handler back to the old PHP CGI binary.
# It does NOT delete either PHP installation or restore all IIS configuration.

$ErrorActionPreference = "Stop"

# EDIT THESE VALUES before running.
$SiteName = "Default Web Site"
$HandlerName = "PHP_via_FastCGI"
$OldPHP = "C:\PHP\8.2.27\php-cgi.exe"
$AppPoolName = "REPLACE_WITH_YOUR_APP_POOL"

$appcmd = "$env:windir\System32\inetsrv\appcmd.exe"

# Require elevation.
$currentIdentity = [Security.Principal.WindowsIdentity]::GetCurrent()
$principal = [Security.Principal.WindowsPrincipal]::new($currentIdentity)
if (-not $principal.IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)) {
    throw "Open PowerShell as Administrator and run the script again."
}

if (-not (Test-Path -LiteralPath $appcmd)) {
    throw "IIS appcmd.exe not found: $appcmd"
}
if (-not (Test-Path -LiteralPath $OldPHP)) {
    throw "Old PHP CGI executable not found: $OldPHP"
}
if ($AppPoolName -eq "REPLACE_WITH_YOUR_APP_POOL") {
    throw "Edit `$AppPoolName in this script to the real application pool name."
}

Write-Host "`nRollback target:" -ForegroundColor Cyan
Write-Host "Site:       $SiteName"
Write-Host "Handler:    $HandlerName"
Write-Host "Old PHP:    $OldPHP"
Write-Host "App pool:   $AppPoolName"

Write-Host "`nCurrent handler configuration:" -ForegroundColor Yellow
& $appcmd list config "$SiteName" /section:system.webServer/handlers
if ($LASTEXITCODE -ne 0) { throw "Could not read handler configuration. No change made." }

Write-Host "`nFastCGI registrations:" -ForegroundColor Yellow
& $appcmd list config /section:system.webServer/fastCgi
if ($LASTEXITCODE -ne 0) { throw "Could not read FastCGI configuration. No change made." }

Write-Host "`nType ROLLBACK to proceed with this handler change."
$confirmation = Read-Host "Confirmation"
if ($confirmation -cne "ROLLBACK") {
    Write-Host "Cancelled. No changes made." -ForegroundColor Yellow
    exit 0
}

# Preserve the current IIS state immediately before the rollback.
$backupName = "BeforeRollbackPHP8235_$(Get-Date -Format 'yyyyMMdd_HHmmss')"
& $appcmd add backup $backupName
if ($LASTEXITCODE -ne 0) {
    throw "Could not create IIS safety backup. No handler change made."
}
Write-Host "Created IIS backup: $backupName" -ForegroundColor Green

# Register old PHP with FastCGI if not already registered.
$fastCgiOutput = (& $appcmd list config /section:system.webServer/fastCgi 2>&1 | Out-String)
if ($fastCgiOutput -notmatch [regex]::Escape($OldPHP)) {
    Write-Host "Old PHP is not visibly registered in FastCGI." -ForegroundColor Yellow
    $register = Read-Host "Register the old PHP CGI executable? Type YES"
    if ($register -ceq "YES") {
        & $appcmd set config /section:system.webServer/fastCgi "/+[fullPath='$OldPHP']" /commit:apphost
        if ($LASTEXITCODE -ne 0) { throw "FastCGI registration failed. Inspect IIS config." }
    } else {
        throw "Stopped before changing the handler because old PHP is not registered."
    }
}

# Update only the selected handler on the selected site.
& $appcmd set config "$SiteName" /section:system.webServer/handlers "/[name='$HandlerName'].scriptProcessor:$OldPHP" /commit:apphost
if ($LASTEXITCODE -ne 0) {
    throw "Handler update failed. Inspect IIS configuration and the safety backup."
}

# Recycle only the selected application pool.
& $appcmd recycle apppool /apppool.name:"$AppPoolName"
if ($LASTEXITCODE -ne 0) {
    Write-Warning "App pool recycle returned a non-zero code. Check IIS state manually."
}

Write-Host "`nResulting handler configuration:" -ForegroundColor Cyan
& $appcmd list config "$SiteName" /section:system.webServer/handlers

Write-Host "`nNext: restore the old php.ini if needed, browse the Yii application, inspect logs, and confirm the web runtime reports the old PHP version." -ForegroundColor Green

How to run the script

PowerShell · run instructions
# Save the script to this path, then edit its values first.
notepad "C:\PHPUpgrade\Rollback-PHP-8235.ps1"

# Run in an elevated PowerShell session.
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
& "C:\PHPUpgrade\Rollback-PHP-8235.ps1"

The execution-policy change applies only to the current PowerShell process. Follow your server's script-signing and change-control rules if they are stricter.
